## 1. 인증 / 공통

- 인증키: `<REDACTED — config.json / .env 에서만 읽는다>`
  (파일 `C:\Users\pjy09\_stock_tools\_dart\config.json`, 환경변수 `DART_API_KEY` 로도 주입 가능)
- 베이스: `https://opendart.fss.or.kr/api/{endpoint}.json`
- status 코드
  - `000` 정상 / `013` 조회된 데이타가 없습니다 (= 정상 0건) / `101` 잘못된 URL(엔드포인트 오타)
  - `013` 은 **에러가 아니다**. `list: []` 로 정규화해서 쓸 것.
- 응답 본문은 UTF-8 이지만 Windows 콘솔로 바로 출력하면 깨진다. `sys.stdout.reconfigure(encoding="utf-8")` 필수.

## 2. ★ 함정: 날짜 필터는 "최초 공시 접수일", 반환 rcept_no 는 "최신 정정본"

`bgn_de`/`end_de` 는 **원 공시의 접수일자**로 필터하는데, 돌려주는 `rcept_no` 는 **정정본의 접수번호**다.
실측 (SK하이닉스 `piicDecsn`, 원본 `20260624000420` → 정정본 `20260710000008`):

```
bgn_de=20260623 → 000 ['20260710000008']
bgn_de=20260624 → 000 ['20260710000008']     ← 경계 = 원본 접수일 2026-06-24
bgn_de=20260625 → 013 []                      ← 정정본 접수일(07-10)이 창 안인데도 0건!
bgn_de=20260710 → 013 []
```

동일 동작을 `tsstkAqDecsn` 에서도 확인(삼성 2024 건, 경계 = 2024-11-18):

```
bgn_de=20241118 → 000 ['20241118000328']
bgn_de=20241119 → 013 []
```

**따라서 "최근 1개월"처럼 좁은 창으로 조회하면 진행 중 프로그램을 통째로 놓친다.**
`dart_source.py` 는 기본 `bgn=20240101` 로 항상 넓게 조회한다.

### 3-2. 정정은 실제로 일어난다 — 감시 로직이 필요한 이유

2024-01-01~2026-09-01 전수 조회에서 삼성전자는 **자기주식취득결정을 3번 정정**했다:

```
2024-11-18 | 20241115000375 | 주요사항보고서(자기주식취득결정)        ← 원본
2024-11-18 | 20241118000171 | [기재정정]주요사항보고서(자기주식취득결정)
2024-11-18 | 20241118000328 | [기재정정]주요사항보고서(자기주식취득결정)  ← API 가 반환하는 건
2025-02-18 | 20250218000019 | 주요사항보고서(자기주식취득결정)        ← 원본
2025-02-18 | 20250218001596 | [기재정정]주요사항보고서(자기주식취득결정)  ← API 가 반환하는 건
```

`tsstkAqDecsn` 는 이 중 **최신 정정본 하나만** 반환한다(원본·중간본은 목록에 없음).
2024년 정정 내용은 원문의 `정 정 신 고 (보고)` 블록에서 확인했고, 바뀐 것은
`10. 1일 매수 주문수량 한도 — 기타주식: 691,204 → 691,203` 뿐이었다(취득예정수량·기간 불변).

**운영 규칙**
1. 매 갱신마다 `tsstkAqDecsn` 를 다시 호출한다 → 정정이 나면 수량/기간이 자동으로 갱신된다.
2. 동시에 `list.json` 에서 `report_nm` 에 `정정` + `자기주식취득결정` 이 함께 든 건을 스캔해
   **정정이 발생한 사실 자체를 대시보드에 배지로 노출**한다.
   (구현: `check_program_amended()` → `{"amended": bool, "amend_filings": [...]}`)
3. 정정본 원문 앞머리에는 `정 정 신 고 (보고) / 1. 정정대상 공시서류 / 3. 정정사항 / 정 정 전 / 정 정 후`
   테이블이 붙는다. 무엇이 바뀌었는지 보여줘야 하면 `fetch_document_text()` 로 이 블록을 파싱하면 된다.

## 5. `aq_wtn_div_ostk` / `eaq_ostk` 의 의미 (임무 4)

취득결정 공시 서식 **`8. 취득 전 자기주식 보유현황`** 표를 그대로 API 필드로 옮긴 것이다.
"**이번 취득을 시작하기 직전에 회사가 이미 들고 있던 자기주식**"이며, 이번에 살 예정 수량이 아니다.

| 필드 | 서식 항목 | 뜻 |
|---|---|---|
| `aq_wtn_div_ostk` | 배당가능이익 범위 내 취득(주) — 보통주식 | 상법 §341 에 따라 **배당가능이익을 재원으로** 취득해 보유 중인 보통주 |
| `aq_wtn_div_ostk_rt` | 〃 비율(%) | **보통주 발행주식총수** 대비 비율 (소수 1자리 반올림) |
| `aq_wtn_div_estk` / `_rt` | 〃 기타주식 | 우선주. 비율 분모는 **우선주 발행주식총수** |
| `eaq_ostk` | 기타취득(주) — 보통주식 | 배당가능이익 재원이 **아닌** 경로로 들어온 자기주식 (상법 §341조의2: 합병·주식교환·단주처리, 주주 매수청구, 담보권 실행, 교환사채 콜옵션 행사 등) |
| `eaq_ostk_rt` | 〃 비율(%) | 보통주 발행주식총수 대비 |
| `eaq_estk` / `_rt` | 〃 기타주식 | 우선주 |

**왜 나누는가**: 배당가능이익 범위 내 취득분은 **소각·처분이 자유**롭고 배당가능이익 한도를 소진한다.
기타취득분은 취득 근거가 다르고 상법상 **처분 의무(상당 기간 내 처분)** 가 걸릴 수 있어 성격이 다르다.
그래서 같은 공시 안의 `【자기주식 취득금액 한도】` 표도 배당가능이익 기준으로만 계산된다.

비율 분모 실증:
- 삼성 `aq_wtn_div_ostk` 79,870,794 ÷ 5,846,278,608 = 1.366% → 공시 `1.4` ✔
- 삼성 `aq_wtn_div_estk` 13,603,461 ÷ 815,974,664(2025말 우선주) = 1.667% → 2026-01 공시 `1.7` ✔
- 하이닉스 `aq_wtn_div_ostk` 1,625,696 ÷ 730,492,365 = 0.223% → 공시 `0.2` ✔
- 하이닉스 `eaq_ostk` 73 → `0.0` ✔

두 회사 실측값:

| | `aq_wtn_div_ostk` | `eaq_ostk` | 합계(= 취득 전 총 보유) |
|---|---|---|---|
| 삼성 20260821000616 | 79,870,794 (1.4%) | `-` (0) | 79,870,794 |
| 하이닉스 20260819000254 | 1,625,696 (0.2%) | **73** (0.0%) | 1,625,769 |

하이닉스의 `eaq_ostk` 73주 정체는 공시 원문에 적혀 있다:
> `상기 '8. 취득전 자기주식보유현황 - 기타취득(보통주식)' 자기주식수는 당사가 2023년 4월 11일 발행한 교환사채의 조기상환 청구권(Clean Up Call Option)을 2026년 5월 중 행사함에 따라 발생한 기타 취득분입니다.`

**대시보드 처리**: 진행률 카드의 "취득 전 보유"는 `aq_wtn_div_ostk + eaq_ostk` 를 쓰고,
"취득 완료 시 예상 보유"는 여기에 `aqpln_stk_ostk` 를 더한다(`projected_treasury_after`).

### 진행 중 판별 로직
```python
def is_program_active(program, today=None):
    today = today or date.today()
    s = parse_kdate(program["period_start"])   # aqexpd_bgd
    e = parse_kdate(program["period_end"])     # aqexpd_edd
    return bool(s and e and s <= today <= e)
```
날짜 문자열은 `"2026년 08월 24일"` 형식이라 `parse_kdate()` 가 한글/ISO/YYYYMMDD 를 모두 흡수한다.

## 10. 알려진 한계 / 열린 항목

1. 휴장일은 `data/holidays_kr.json`(KRX 공식, 2025~2027)에 의존한다. 이 파일이 없어지면
   2025·2026년이 폴백 표로 떨어지므로 `HOLIDAY_SOURCE` 를 확인할 것. 2024년은 항상 폴백
   (네이버 실측으로 만든 값이라 정확하지만 KRX 원본은 아님).
   임시공휴일이 새로 지정되면 파일을 갱신해야 한다(`market_data.fetch_krx_holidays`).
2. `stockTotqySttus` 는 분기보고서에서 표가 비어 올 수 있고, 최신 증자·소각을 반영하지 못한다.
   → `fetch_shares_outstanding()` 의 보정·교차검증을 반드시 통과시킬 것(`crosscheck_ok`).
3. `주식소각결정` / `자기주식취득결과보고서` / `자기주식처분결과보고서` 는 **전용 API 엔드포인트가 없다**.
   `list.json` 의 `report_nm` 으로 탐지하고 `document.xml` 원문을 파싱해야 한다
   (`total_shares_from_cancel_doc()` 이 그 예).
4. **DART 에는 일별 실제 매수 체결량이 없다.** 진행률의 분자는 KIND(`treasurystk.do`)에서 와야 한다.
   DART 는 분모(취득예정수량)·기간·정정 여부·발행주식총수 담당.
5. 취득 완료 시 `자기주식취득결과보고서` 가 올라온다(예: 삼성 20260424000778).
   `list.json` 감시로 "완료" 확정 이벤트를 잡을 수 있다.
6. 원문 캐시는 `data/_dart_cache/doc_{rcept_no}.txt`. 정정본이 새로 뜨면 rcept_no 가 바뀌므로 캐시 무효화 걱정 없음.
